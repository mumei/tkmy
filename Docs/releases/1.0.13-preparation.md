# TKMY 1.0.13候補の検証

2026年10月14日。Codexの残量％がステータスバーに表示されない問題を修正する候補です。ソースの版は1.0.13／build 20とし、既存順序の11言語でリリースノートを用意しました。正式ビルド番号はReleaseワークフローで上書きされます。

## Nodeの起動経路で取得失敗を再現

インストール済みCodex CLI 0.137.0の起動入口は、`#!/usr/bin/env node`を使うスクリプトでした。次のPATHではNodeを解決できず、起動に失敗します。

```sh
env PATH=/usr/bin:/bin:/usr/sbin:/sbin ~/.bun/bin/codex --version
```

Node経由の起動に失敗すると、1.0.12では必須になったアカウント確認も失敗し、現在の残量は空になります。ログ由来の匿名残量を現在値として表示する処理は1.0.12で削除されています。

同じMacでネイティブのCodex実行ファイルを使うと、公開プロトコルの`account/read`と`account/rateLimits/read`は成功し、取得前後のアカウントも一致しました。今回確認した応答には既存パーサーが対応しており、API形式の変更は確認していません。`account/read`の`refreshToken`は`false`を指定します。[公式仕様](https://learn.chatgpt.com/docs/app-server#auth-endpoints)

修正後はNode起動スクリプトを判別し、PATHとHomebrewの一般的な配置先からNodeを探して、実行ファイルを明示します。Codex.appのネイティブ実行ファイルや、別の起動スクリプトを直接使う経路は維持します。認証情報や認証の生応答は記録しません。

## 未取得と0％を区別する

残量がない場合、従来のステータスバーは数値に「—」を表示しながら、グラフには0％を渡していました。修正後は数値を「—」、メーターを「?」で表示します。確認できた0％は従来どおり空のメーターで表示します。

アカウント確認の前後比較、切替通知を受けた場合の拒否、匿名履歴を現在の残量に使わない条件は維持します。保存済みの匿名履歴を使って、取得失敗時の残量を補いません。

## 検証範囲と公開前に残る確認

ローカルの全テスト、追加した回帰テスト、任意実行の実アカウント取得テスト、標準の`Scripts/build-app.sh`によるビルドとアドホック署名検証は成功しました。全ChangeLogの形式検証、plist検証、スクリプト構文検証も成功しています。初回の全テスト実行では既存のCodex／Claudeの終了待ちテストが2秒の条件を超えました。偽サーバーの10秒／30秒の終了を待った場合は失敗する条件を保ち、実行時間の上限を5秒にして再確認しました。通常CIの結果はPRで別に確認します。

- 合成のNode起動入口で、制限PATHでの修正前の起動失敗と、修正後の取得成功を検証します。取得中のアカウント変更・変更通知・実行できないNodeも対象です。
- 任意実行の実環境テストは、`TKMY_LIVE_CODEX_TEST=1`を指定し、`codexIdentifiedQuotaWorksWithInstalledLauncherAndGUIPathWhenRequested`を実行します。制限PATHでも修正済みProviderから実アカウントの残量を取得できることを確認済みです。通常CIはこの実アカウントテストを実行しません。
- 実際の`NSStatusItem`と`NSStatusBarButton`を生成し、合成の96％・0％・未取得でタイトルと画像を確認します。匿名履歴の97％を現在値に使わないことも検証します。`.build/ui-snapshots/statusbar-presentation-*.png`は実ボタンの表示内容をもとにした合成プレビューであり、稼働中アプリのスクリーンショットではありません。
- 稼働中TKMYのプロセス環境は取得していません。このMacの実行環境で起動失敗を再現しましたが、起動中TKMYのPATHと直接照合した結果ではありません。
- 稼働中アプリは置換・再起動していません。Finder／ログイン項目から起動した候補版の実画面、メニューバーの幅不足やノッチとの関係、更新後の表示回復は公開前の確認として残ります。
- マージ、タグ作成、リリース公開、Developer ID署名、公証、Sparkle更新配信は今回の対象外です。
