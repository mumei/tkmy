## 実アカウント取得は確認が残る

Claude一般利用枠の14テスト、関連する既存テスト、ローカルアプリのビルドは実装時に成功しています。一般の7日枠を優先し、5時間枠だけ取得できた場合は期間を表示します。モデル固有枠やコンテキスト使用率は使用しません。

取得は公式SDKの実験的な機能に依存します。Claude Code 2.1.289は今回確認した最も古い仕様に合わせた対応条件で、APIの導入版を意味しません。このMacのCLIは2.1.76のため、実アカウントでの割合取得は未確認です。

対応CLIのあるMacで、同じログインの`/usage`に一般利用枠があることを確認し、候補版の「残量パーセントを表示」をONにしてClaudeメニューの「再集計」を選びます。同じ期間の割合とリセット時刻を比較してください。確認結果には版、設定、対象枠の有無、割合または「—」の表示だけを残し、認証情報やCLIの生応答は含めません。手順の詳細は[日本語README](../../README_ja.md#claude-codeの利用枠残量)を参照してください。

## ローカル成果物は配布用署名の前段階

標準の`Scripts/build-app.sh`で`.build/app/TKMY.app`を作成しました。これはアドホック署名の確認用アプリです。標準CI用の`Scripts/package-build.sh`で作るZIPとSHA-256は、`.build/release-candidates/1.0.10/`に保存しました。既存の`.build/release-assets`は退避・復元し、保持しています。

ローカル検証済み：11言語ChangeLogの検証、全shellスクリプトの構文確認、Info.plistの形式・版番号確認、`git diff --check`、標準アプリビルド、`codesign --verify --deep --strict`、ZIPのSHA-256照合。ビルドは成功しましたが、sandboxでSwiftPMのユーザー用cacheへ書けない旨の警告が出ています。

成果物はarm64の確認用アプリと`TKMY-07d777a-adhoc.zip`／同`.sha256`です。ZIP名は実装コミットに対応し、アプリのメタデータは1.0.10／build 17です。ZIPのSHA-256は`b5559bc30ce2202022960bb9a9f9ad15f74935030e54140961100e7ced213c4f`。既存release-assetsは内容のハッシュを照合して復元を確認しました。

日本語はnatural-japaneseのquick工程でlintと見出し・全文の確認を行いました。ノートと設計書の価格節には文長の均質さに関する警告が各1件あり、短い仕様説明と表の形式を優先して維持しました。準備記録とREADMEの追記には検出事項がありません。候補版のDeveloper ID署名、Apple公証、Sparkle署名、DMG作成は未実施です。稼働中のアプリは置換していません。

## 公開時はmainの標準Release経路を使う

公開実行の依頼を受けた後、次の順序で進めます。

1. 料金PRとの統合順序と正式版番号を確定し、Claude変更をmainへ統合する。現在はローカルブランチのため、mainに含まれていません。
2. 実アカウント確認の結果を反映し、mainのCIで全テスト、11言語ChangeLog検証、アプリビルドが成功したことを確認する。Releaseワークフロー自体にはテスト工程がありません。
3. `release`環境の証明書・公証キー・Sparkle署名キーの有効性を確認する。必要なsecret／variableの名前は登録済みですが、有効期限や値の正しさは今回確認していません。
4. `.github/workflows/release.yml`をmainから実行する。標準経路がDeveloper ID署名、公証、ZIP、署名済みappcast、DMG、公証・staple、GitHub Release公開を行います。
5. DMG／ZIPと各SHA-256、11言語ノートを含むappcastを確認し、既存版からのSparkle更新を実機で確認する。

`publish=false`でもAppleへの公証送信とGitHubへの成果物アップロードは行われます。今回のローカル準備では実行していません。公開時の版・ビルド番号は、その時点の正式版とRelease実行番号を照合します。

直近の標準経路の成功例は[1.0.8のRelease実行](https://github.com/mumei/tkmy/actions/runs/36233383875)です。今回の候補が同じ署名・公証工程を通過したことを示すものではありません。
