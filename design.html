TKMY / トークン見えるやつ / technical design

ローカルの利用記録を、静かに集計する。

CodexとClaude CodeのJSONL利用記録を端末内だけで解析し、2つの独立したメニューバー項目へトークン数と推定金額を反映する。設計の中心は、ソース別アダプター、冪等な差分集計、版管理された価格表、最小限の永続化である。

設計判断

MVPの責務を「ローカルログの読取・日別集計・USD金額推定・表示・公式更新」に限定する。金額は参考値として明示し、為替換算、クラウド送信、プロジェクト別分析は設計に含めない。

配布形態

Mac App StoreではなくDeveloper IDによる直接配布。ログディレクトリへアクセスするためApp Sandboxは使用せず、Hardened Runtimeと公証を有効にする。

UI技術

AppKitのNSStatusItemをCodex／Claude Code用に1つずつ生成し、NSPopoverの内容をSwiftUIで構築する。

並行処理

UsageCoordinatorをactorとし、ファイル監視・解析・SQLite書込を直列化する。UI更新だけを@MainActorへ送る。

永続化

macOS標準SQLiteをWALモードで使用。生のプロンプト、回答、ソースコードは保存しない。

集計基準

時刻はUTCで保存し、表示時のmacOSローカルタイムゾーンで日付へ変換する。タイムゾーン変更時は日別集計を再構築する。

金額基準

ログ内のcostUSDを優先し、存在しない記録は同梱したモデル別価格表からUSDを算出する。価格不明は0として扱わず、算出不能状態を保持する。

OSS方針

アプリ、テストfixture、CI、署名を除く更新設定を単一リポジトリで公開。公式署名用の秘密情報だけをGitHub Environment Secretsへ置く。

ccusage参照範囲

ccusage/ccusageは、ローカルのエージェント利用記録をソース別アダプターで読み、日・月・セッション単位へ集計するMITライセンスの実装である。本設計はデータ意味論とcost modeを参照し、CLIやRust実装そのものは取り込まない。

ログ取得

CodexAdapter

  • ${CODEX_HOME:-~/.codex}/sessions/**/*.jsonl
  • archived_sessions/**/*.jsonlも読む
  • 同じ相対パスはactive sessionsを優先
  • event_msg / token_countだけを抽出
  • last_token_usageをturn差分として優先
  • 累積値だけなら直前値との差を復元

ClaudeAdapter

  • ~/.claude/projects/**/*.jsonl
  • ~/.config/claude/projects/**/*.jsonl
  • CLAUDE_CONFIG_DIRの複数パスに対応
  • nested sessionとlegacy flat fileを再帰探索
  • message usageとadvisor usageを別event化
  • 壊れたJSONL行はskipし診断件数へ加算

初回scanと差分scan

  1. discovering既定パスと環境変数から存在するsource rootを解決する。
  2. indexingJSONLのpath、size、mtime、inodeを収集し、前回cursorと比較する。
  3. reading追記ファイルはlastOffsetから読む。置換・縮小されたファイルは先頭から再評価する。
  4. committingevent upsert、daily aggregate、cursor更新を1 transactionで確定する。
  5. watchingFSEventsをdebounceし、変更されたrootだけを再scanする。
ファイルが書込途中の場合

末尾の改行で閉じていない行は未確定としてcursorを進めず、次回変更時に再読する。1行のparse失敗でファイル全体を失敗させない。

金額計算

金額は請求額ではなくUSDの推定値である。UIは必ず「推定」と表示し、価格表の日付と未算出レコードの有無を追跡可能にする。

  1. sourceイベントにcostUSD相当があれば、その値を最優先する。
  2. calculatesource金額がなければ、model aliasを解決して入力、出力、cache create 5分／1時間、cache readの各単価を適用する。
  3. tierモデルが長文脈価格を持つ場合は、価格表に記録したthresholdと課金方式をrequest単位で適用する。
  4. unknownmodelまたは必要な単価が不明なら金額をnilとし、unknown event数とtoken数を集計する。
  5. aggregate全件算出可能なら通常金額、一部不明なら「$X.XX+／一部算出不可」、全件不明なら「算出不可」とする。
項目方針理由
通貨USD固定、内部値は整数micro-USD浮動小数点誤差と為替レート依存を避ける
丸めDecimalで積算後、event単位でmicro-USDへhalf-up同じ入力から常に同じ集計値を得る
価格源OpenAI／Anthropic公式料金表の検証済みsnapshot公開単価が確認できたモデルだけを算出対象にする
更新CIで差分をreviewし、アプリreleaseへ同梱実行時通信を増やさず再現可能にする
履歴再計算catalog更新時にderived daily costを再構築source eventを変更せず計算根拠を統一する
表示精度通常は小数2桁、0.01 USD未満は<$0.01ゼロとの誤認を防ぐ

価格表の信頼境界

価格snapshotの取得元URL、取得日時、SHA-256、生成scriptを公開リポジトリへ保存する。自動更新PRはテストと人手reviewを通し、アプリが外部価格APIへ直接接続することはない。

daily_cost(

  pricing_catalog_version TEXT NOT NULL,

  • DB配置は~/Library/Application Support/TKMY/usage.sqlite3。
  • WAL、foreign keys、busy timeoutを起動時に設定する。
  • migrationは単調増加するschema versionで管理し、失敗時は旧DBを破壊しない。
  • 「履歴を削除」はevents、daily usage、cursorをtransactionで削除し、次回scanの扱いを利用者へ明示する。
  • origin pathはSHA-256 hashのみ保存し、ユーザー名やproject pathをDBへ残さない。
  • 価格表更新時はdaily_costだけを再構築し、usage_eventsとsource記録済み金額は変更しない。

  • hoverは800ms後、keyboard focusとclickは即時にpopoverを開く。
  • 同時に開けるpopoverは1つ。Codexを開いた状態でClaudeを選ぶとCodexを閉じる。
  • 詳細表示はNSPopoverの自動位置補正を使わず、固定サイズの非アクティブNSPanelを使用する。status itemの画面座標から中央直下を計算し、操作したディスプレイのvisible frame内へ8pt余白で収める。
  • Escape、外側click、status item再clickで閉じる。
  • 非アクティブ状態でhover表示した場合も、表示中だけローカル／グローバルのmouse-downを監視し、最初の外側clickで閉じる。popover内と対象status itemのclickは除外する。
  • Codexの横棒と数値は、最新のrate_limitsにある10,080分の一般週次枠を使い、100 - used_percentを「残り58%」の形式で表示する。モデル固有枠は一般枠と混在させない。
  • 上限情報を取得できないツールでは推測値を作らず「残り—」とする。正確な当日token数、使用済み率、リセット日はツールチップに、推定金額は詳細画面に表示する。
  • 設定画面から「カラーバー」「モノクロバー」「分割」「カラー分割」「ドット」「リング」「ゲージ」「バッテリー」「縦バー」「数字のみ」の10種類をプレビュー付きで選択でき、Codex／Claude Codeの両メニューへ即時反映する。カラーはCodexを青、Claude Codeをオレンジとする。ラベルと残量パーセントは個別に表示／非表示を選べ、グラフをラベルの左または右へ配置できる。両方の文字を隠すとグラフのみ、残量パーセントだけを隠すとラベルとグラフだけになる。ただし「数字のみ」で両方を隠した場合は、設定導線を失わないようソース名を表示する。
  • heatmapは12か月固定で1マス1日とする。期間内の最大トークン数を100%とする連続的な線形尺度で算出し、ティール、グリーン、イエロー、オレンジ、レッドのカラーレンジを補間して段階へ丸めない。色に加えてVoiceOver labelで正確な値を伝える。クリックした日は固定選択として保持する。各マスのhover中はその日を優先して下部の日別詳細へ即時表示し、hover終了時は最後にクリックした固定選択日へ戻す。
  • 今日の4指標は1枚の概要面へまとめ、合計を26pt、入力・出力・推定金額を20ptのtabular numbersで横並び表示する。同じ概要面の右上に、今日を含む直近30日間の「直近30日の推定合計（USD）」を小数第2位まで表示する。月境界に関係なく30暦日を対象とし、価格不明の記録を含む場合は算出済み額に「+」を付け、全件算出不能なら「算出不可」とする。選択日の6指標は16ptの3列×2段とし、桁数によるフォント縮小を行わない。その下にモデル別トークン消費を能力クラス順の4列グリッドで折り返し表示し、各モデルの値は見出しと重複するtokens単位を付けず数値だけを表示する。Codexは高性能、標準、軽量、内部処理の順、Claude CodeはOpus、Sonnet、Haikuの順とし、同じクラスでは新しい世代を先にする。消費量によって並びを変えず、分類できないモデルと「モデル記録なし」は末尾へ置く。モデル情報がない日にも実データ1行分の高さを予約し、更新中スピナーと更新時刻にも同一寸法の領域を割り当てることで、選択日や更新状態にかかわらず日別詳細の表示位置を固定する。水平スクロールは使わない。価格表のaliasは正規モデル名へ統合し、利用記録にモデル名が含まれない分は「モデル記録なし」と表示してツールチップで意味を説明する。
  • heatmapのセル幅はpopoverの利用可能幅から動的に算出し、52週を左右の余白なく配置する。注意書きと価格表更新日は下端の固定フッターへ集約し、本文の高さを変えない。
  • heatmapの色相はtoken量を線形に表し、利用なしは中立色、利用量の少ない日をティール、最大の日をレッドとして5色間を連続補間する。Codex／Claude Codeで同一尺度を使い、相互比較できるようにする。金額は当日概要と選択日詳細へ別項目で表示し、同じ色尺度へ混在させない。
  • 推定金額の補足から価格表の更新日、算出方法、価格不明モデルを確認できる。
  • 各status itemの右クリックメニューからネイティブ設定ウィンドウを開く。ウィンドウは操作したstatus itemが属するディスプレイの表示可能領域中央へ配置する。
  • 設定画面では表示言語、ログイン時の起動、ホバー表示、自動更新確認、メーターデザイン、Codex／Claude Code各メニューの表示を即時反映する。初回起動時はLocale.preferredLanguagesの先頭から対応言語を選び、未対応の場合は英語へフォールバックして保存する。表示言語はmac-capslockと同じ11言語（英語、日本語、ドイツ語、簡体字中国語、フランス語、韓国語、スペイン語、イタリア語、ベトナム語、タイ語、繁体字中国語）とする。設定導線を失わないよう、2つのメニューを同時には非表示にできない。情報セクションにはバージョン、MIT License、制作者だけを表示し、内部のデータ処理説明は置かない。制作者の@yuto_uehara_sanはhttps://x.com/yuto_uehara_sanへのリンクとする。

更新とOSS公開

mac-capslockと同じくSparkle 2、GitHub Releases、GitHub Pages appcastを使う。ただし本プロジェクトはアプリ全体を公開し、非公開コード層を持たない。

  1. tagvX.Y.Zの保護タグでrelease workflowを開始。
  2. verifyunit、fixture、integration、SwiftLint、secret scanを実行。
  3. buildarm64／x86_64のUniversal BinaryをRelease構成で生成。
  4. signDeveloper ID署名、Hardened Runtime、Apple公証、stapleを確認。
  5. packageZIP生成後、Sparkle EdDSA署名を付与しDraft Releaseへ配置。
  6. publishRelease公開後、最後にGitHub Pagesのappcast-v1.xmlを更新。
