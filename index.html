01 / Overview

目的と対象

日々のAIコーディング利用量と概算コストを、作業を中断せずに把握できる状態をつくる。対象はCodexまたはClaude Codeを日常的に利用するmacOSユーザーとする。

採用する表示

CodexとClaude Codeを別々のメニューバー項目として表示する。それぞれが独立した横向き棒グラフ、利用制限の残量、詳細表示を持つ。

公開方針

アプリ本体、ビルド手順、CI、更新設定を単一の公開GitHubリポジトリで提供する。公式バイナリは同じリポジトリのReleasesとGitHub Pagesから配布する。

02 / Behavior

表示と操作

常時見る情報と、必要なときだけ開く情報を分離する。

通常表示

  • Codexの独立メーター
  • Claude Codeの独立メーター
  • 取得可能な利用制限の残量
  • ツール別の取得エラー状態

簡易詳細

  • ツール別消費量
  • 入力／出力の内訳
  • 本日の推定金額（USD）
  • 日別トークン消費履歴
  • 最終更新時刻

クリック時

  • 選択したツールのポップオーバーを表示
  • そのツールだけの12か月ヒートマップ
  • 選択日の正確なトークン数と推定金額
  • Escapeで閉じる

操作互換

  • マウスオーバーで簡易詳細
  • キーボードフォーカスでも同じ情報
  • タッチパッドのクリックでも開閉
  • Escapeで閉じる

03 / Functional

機能要件

FR-01
メニューバー常駐
終了操作まで常駐し、Dockへの表示は設定で選べる。
FR-02
自動起動
設定画面からmacOSログイン時の起動を切り替えられる。
FR-03
Codex集計
ローカルの利用記録からトークン数を取得する。
FR-04
Claude Code集計
ローカルの利用記録からトークン数を取得する。
FR-05
当日集計
端末のローカル日付で0時から現在までを集計する。
FR-06
独立メーター
CodexとClaude Codeを別項目とし、取得できた一般利用制限の残量を横向き棒グラフとパーセントで表示する。上限情報がない場合は推測せず「残り—」とする。
FR-07
ツール別詳細
ホバー、フォーカス、クリックで、選択したツールだけの当日内訳と日別履歴をポップオーバー表示する。
FR-08
日別履歴
選択したツールのポップオーバー内に、直近12か月のトークン消費をカレンダー型ヒートマップで表示する。
FR-09
日付詳細
ヒートマップの日付へマウスを置くか選択すると、その日の合計、入力／出力、キャッシュ、推定金額へ詳細表示が切り替わる。日付や桁数が変わっても数値のフォントサイズは固定する。
FR-10
差分再集計
利用記録の変更を検知し、差分のみを再集計する。
FR-11
手動更新
詳細画面から再集計を実行できる。
FR-12
設定
Codex／Claude Codeそれぞれのメニュー表示、メーターデザイン、ホバー表示、自動起動、更新の自動確認を変更できる。設定への導線を維持するため、ツールのメニューは少なくとも片方を表示する。
FR-13
アプリ更新
Sparkle 2を使用し、更新の自動確認と「アップデートを確認…」による手動確認に対応する。
FR-14
更新の真正性
更新ZIPのSparkle EdDSA署名、アプリのDeveloper ID署名、Apple公証をすべて検証する。
FR-15
推定金額
CodexとClaude Codeごとに、本日および選択日の利用金額を米ドルで表示する。ログ内の金額を優先し、存在しない場合はモデル別価格表から算出する。
FR-16
価格情報の明示
金額が推定値であること、使用した価格表の更新日、価格不明モデルの有無を確認できる。価格不明を0ドルとして表示しない。
FR-17
表示言語
初回起動時はmacOSの優先言語から対応言語を自動選択する。英語、日本語、ドイツ語、簡体字中国語、フランス語、韓国語、スペイン語、イタリア語、ベトナム語、タイ語、繁体字中国語から選択でき、メニューバー、詳細画面、設定画面へ即時反映する。

04 / Aggregation

集計仕様

総トークン数 = 入力トークン + 出力トークン
推定金額（USD） = Σ（モデル別・トークン種別の使用数 × 単価）

取得できる場合は、キャッシュ作成、キャッシュ読み込み、推論関連トークンを別項目として保持する。記録にはツール名、セッションID、日時を紐づけ、同じ記録を再読込しても重複計上しない。

金額は請求額ではなく参考値とする。ログにcostUSD相当の金額がある記録はその値を優先し、それ以外はモデル名と同梱価格表を使って入力、出力、キャッシュ作成、キャッシュ読み込みを別々に計算する。金額表示はUSD固定かつ小数第2位までとし、為替換算は行わない。

一部のモデルだけ価格を特定できない日は、算出できた合計へ「一部算出不可」を併記する。すべて算出できない場合は「算出不可」と表示し、$0.00とは表示しない。ヒートマップの濃淡は引き続きトークン消費量を表し、金額とは連動させない。

表示は1,000以上をK、1,000,000以上をMで省略する。詳細画面では省略前の正確な値も表示する。

棒グラフの満杯基準

CodexのJSONLに記録された一般週次枠のused_percentから残量を算出し、100%を満杯、0%を空として表示する。モデル固有枠や過去のトークン最大値は代用しない。

05 / Data

データとプライバシー

収集する

  • 記録日時
  • ツール種別とモデル名
  • トークン数と内訳
  • ログ記録済み金額（存在する場合）
  • 重複防止用識別子

収集しない

  • プロンプト本文
  • 回答本文
  • ソースコード本文
  • APIキーなどの秘密情報

06 / Quality

非機能要件

省資源

  • ファイル変更検知を優先
  • 全履歴の反復走査を回避
  • スリープ復帰後に自動再開

堅牢性

  • 片方のツールがなくても動作
  • 破損記録を隔離
  • 形式変更をエラーとして表示

アクセシビリティ

  • 色だけに依存しない凡例
  • キーボードで操作可能
  • ライト／ダークモード対応

保存

  • 端末内で処理を完結
  • 再起動後も履歴を保持
  • 利用者が履歴を削除可能

07 / Scope

MVP

初期版に含める

  • メニューバー常駐
  • Codex／Claude Code集計
  • ツール別の独立メーター
  • ツール別の当日内訳と推定金額
  • ツール別12か月ヒートマップ
  • ローカル保存
  • 同梱価格表によるUSD換算
  • Sparkle 2によるアプリ更新
  • 完全なソースコード公開

08 / Distribution

OSS公開とアップデート

ソースの透明性と、公式バイナリの真正性を別々に保証する。

完全オープンソース

  • 単一リポジトリでアプリ全体を公開
  • ビルド手順とCIワークフローを公開
  • Sparkle設定とappcastを公開
  • 依存ライブラリとライセンスを明記
  • 公開前にLICENSEを確定

公式アップデート

  • GitHub Releasesで更新ZIPを配布
  • GitHub Pagesでappcast-v1.xmlを配信
  • Universal Binaryを公式CIで生成
  • GitHub用トークンをアプリへ含めない
  • 自動確認を設定から無効化可能
署名とリリース順序

バージョンタグを起点にテスト、Universal Build、Developer ID署名、Apple公証とstaple、ZIP生成、Sparkle EdDSA署名を実行する。Draft ReleaseへZIPを配置して公開した後、最後にappcastを更新する。

秘密情報と修正版

Developer ID証明書、Apple公証資格情報、Sparkle EdDSA秘密鍵は承認付きGitHub Environment Secretsだけに保存し、Pull Requestでは利用しない。公開済み資産は上書きせず、不具合版はappcastから外し、より大きいCFBundleVersionの修正版を公開する。

09 / Acceptance

受け入れ条件

  1. CodexまたはClaude Codeの利用後、消費量が自動反映される。
  2. メニューバーだけでCodexとClaude Codeそれぞれの当日消費量を確認できる。
  3. ホバー、フォーカス、クリックのいずれでも簡易詳細を確認できる。
  4. 選択したツールのポップオーバー内で、直近12か月の日別消費量を確認できる。
  5. 任意の日の正確な数値をCodexとClaude Codeに分けて確認できる。
  6. CodexとClaude Codeそれぞれについて、本日および選択日の推定金額をUSDで確認できる。
  7. 価格不明モデルを含む場合、0ドルと誤表示せず「一部算出不可」または「算出不可」を確認できる。
  8. 再起動後も集計履歴が保持される。
  9. 同じ利用記録が重複計上されない。
  10. プロンプト、回答、ソースコード本文が保存されない。
  11. 公開リポジトリの手順だけでローカルビルドできる。
  12. 公式リリースから署名・公証済みUniversal Binaryを取得できる。
  13. 自動確認と手動確認の両方から、EdDSA署名済み更新を適用できる。
  14. 署名不正、未公証、または改変された更新を拒否できる。
